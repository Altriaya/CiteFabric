# Round 4：跨论文证据检索评测协议

协议版本：0.1-draft，2026-09-09。状态：待审阅的冻结候选；已经运行 opened self-review 开发实验，但尚未完成独立封存或 promotion 评测。

本轮首先回答：在此前未用于开发的论文上，相同预算的 structured_v3 是否比 v2 更经常返回足以审阅问题或论断的证据。算法开发暂停，直到协议、fixture schema、gold rubric 和 pilot 清单完成第一次冻结。默认策略仍为 v2。

配套文件：[fixture schema](fixture.schema.json)、[gold 标注规则](gold-rubric.md)、[默认策略升级门槛](promotion-gate.md)。本目录不属于产品 `schemas/0.1` API；旧 `validate_real_papers.py` 不能直接执行此格式。

## 阶段及隔离

1. **协议冻结。** 固定上述文件、评测工具版本、论文纳入/排除规则、预算、指标、阈值和操作者职责。生成签名或可审计的时间戳记录及各文件 SHA-256。规则发生实质变化须升版本，注明理由，不覆盖旧文件。
2. **Blind pilot。** 选择 4–6 篇新论文，编制约 60 个独立 intent，在查看该批算法输出以前完成查询和 gold。以冻结的 v2/v3 运行。该阶段用于估计可行性、标注分歧和真正的 failure modes，不决定默认升级。
3. **开发与算法冻结。** pilot 开封后整体转入开发集，按问题类别修复并保留全部失败。旧六篇和 pilot 均可回归。冻结候选源码、依赖、解析器、词汇表、参数、提示词（若有）和评测工具；任何能改变检索结果的修改都算算法变更。
4. **最终留出评测。** 累计达到 promotion gate 的规模，并另有足够的全新留出论文。留出集在候选算法冻结后由独立维护者完成，先封存查询和 gold，再运行。盲审完成后才揭示策略身份。
5. **升级决策。** 只用一次性留出结果判定候选是否通过；开发集成绩作为回归附件。失败或统计证据不足则继续显式启用 v3。开封留出集转入开发集，下一候选需要新的留出集。

“累计规模”不表示可以把 pilot、旧六篇和留出集混起来计算泛化分数。论文是划分和统计聚类单位，同一研究的预印本、期刊版、补充材料和高度重叠数据报告归入同一 paper family。

## 盲法的可执行含义

- Gold 标注者先看完整原论文，不看任何候选检索结果。查询编写者不得通过试搜来挑容易命中的问题。
- 检索程序只接收论文、查询及公开参数；gold 独立文件存放，不挂载到执行环境。执行者必要时可接触查询，但不得在留出运行后改算法或人工改写查询。
- 输出审阅者不知道输出来自 v2 还是 v3。按预先固定种子随机化 A/B 顺序，隐藏策略、排名分数、trace 和耗时；保留原文、页码与审阅需要的元数据。映射由维护者保管。输出形态可能泄露策略，须记录盲法局限。
- 同一助手编题、标注、看输出再改代码不属于独立盲测。没有独立维护者或第二位审阅者时，可运行“预注册、自审 pilot”，明确降级；不满足 promotion 条件。SHA-256 只能证明文件未变，不能证明未被看过。
- 第二位 gold 审阅者检查原文和第一份标注；输出评分采用两位审阅者独立打分、随后仲裁，记录仲裁前分歧。复核不调用产品 semantic verifier。

## 语料及题目分布

- Pilot 使用 4–6 个从未用于 CiteFabric 开发的 paper families，至少三个研究领域。最终语料门槛见 gate。以数字原生、可获得固定版本 PDF 的论文为主。
- 至少覆盖：叙述与方法定义、单页结果表格、图注或公式解释、限制与泛化范围。复杂表格、跨页条件、字体异常另外登记，不能看到失败后剔除。
- OCR 必需的扫描稿可预先归为 stress 层，检验明确降级；不把扫描识别能力列为本候选的核心承诺。排除只能在看到结果前按可获得性、权限、重复论文等明确规则执行，并保留排除日志。
- 每个 intent 有含义等价的中英文自然查询；两种语言各运行一次，仍只算一个 intent。不得英文用精心挑选的关键词、中文用复杂问题而声称公平跨语言比较。
- 错误模型、错误数据集、指标方向颠倒、范围过度推广、未报告配置必须覆盖；数值替换、同义改写及中英文共享 parent intent，不增加独立 intent 分母。
- 不预设所有负例都应返回空结果：错误论断可能需要取回真正的反例；未报告配置可能只能确定当前证据不足。
- 先按论文确定预期范围和难度，再编题，不按算法成功率挑选论文。冻结语言等价性复核和原论文审阅记录。

## 实验设置

主任务是**给定论文的证据检索**：已知固定 edition，每题限定同一论文；该结果不能解释为全库搜索能力。跨论文检索应另建任务和分母。

- 主设置：`max_chars=6000`、`max_passages=6`、`allow_abstract=false`，其余开关显式记录。v2/v3 用同一论文集合、PDF、提取快照和请求预算，独立工作区，禁止结果缓存串用。
- 12000 字符设置仅作次要诊断，不用于挽救 6000 字符主门槛。合成测试和旧六篇回归单独报告。
- 固定所有论文导入完成后再检索，避免 FTS 全库统计随运行顺序变化。索引构建失败、解析失败、超时和空结果保留在主分母。
- 记录 git commit、dirty 状态及 diff 哈希、uv.lock 哈希、配置、系统/Python/依赖版本、PDF/提取快照/fixture/gold 哈希、随机种子、时间、错误与重试。发布的评测应使用干净源码。
- 每份来源保留物理页号，gold 另存原文精确跨度和 extraction 文本哈希。Gold 若不能在固定快照重放，标为标注或提取问题，禁止为了锚点通过而重写原文。
- 冷启动导入/索引与热检索分别计时；热检索每种设置交错运行至少三次，以每个 intent 的中位数汇总。每次调用保存证据和完整 MCP 响应，回读验证哈希与偏移。
- 成本计完整 MCP UTF-8 字节，包含 TextContent/structuredContent 的重复封装。若 trace 改为资源读取，另报初始响应和“初始响应 + 一次完整审计读取”，不得只算初始响应宣称总成本下降。token 只在固定真实 tokenizer 下报告；字节、字符均不可替代 token。

## 主指标与结果发布

主指标为人工盲审的 **Evidence Sufficiency Rate（ESR）**：在论文可回答的 intent 上，返回包是否完整覆盖至少一个 gold 最小充分证据集，以及必要的条件关系。完整定义见 rubric。页命中和锚点覆盖降为诊断指标。

按论文先求比例、再对论文等权平均；中英文分别报告，另报合并但不把双语当独立样本。分别报告 supported、contradicted 和 insufficient gold，负例不与正例混成单一“准确率”。

不可回答 intent 没有正向充分证据集，不进入 answerable ESR；单列返回行为、误导性混淆与证据不足标记。空结果不会自动获得“正确拒答”分数；只有接口明确表达对应状态时才能计明确拒答。

所有门槛需同时报告分子/分母、每论文结果、分层结果和置信区间。策略差值采用按 paper family 聚类的配对 bootstrap（10,000 次、种子 20260909），同一论文全部 intent 与双语一起重采样；用重采样差值的 2.5/97.5 百分位为双侧 95% 区间。少量论文的区间可能不稳定，未达门槛即证据不足，不能只报告正向点估计。

公开方法、无敏感信息的汇总、失败分类和可复现命令；论文 PDF 按来源许可处理，封存中的查询/gold 不提前进公开仓库。最终报告应声明这是本语料和任务上的升级证据，不代表所有学科、OCR 或表格语义认证能力。

## 本阶段交付边界

已实现 fixture 关系校验、只读取 queries 的运行器、哈希封存记录、盲审包导出和双人评分汇总，并提供合成契约演示。另已完成 6 篇真实论文、60 个独立 intent 的 opened self-review 开发实验，结果见 [开发实验结果](development-results.md)。该批次由同一操作者编制、开封和复核，不是独立 gold 或盲审结果；协议仍是冻结候选。工具用法见 [操作说明](tooling.md)。下一阶段安排独立维护和标注角色，建立新的封存批次；在 promotion gate 通过以前不修改默认 retrieval。

实现口径补充：MCP 成本按接收的完整 JSON-RPC 响应进行固定格式重序列化计 UTF-8 字节，包含 response id、content 和 structuredContent；不声称测量管道原始空白或网络帧。主报告同时计一次完整证据资源回读的审计总字节。首次遍历单列为 first_pass，只有每个工作区第一次触发索引时具有冷索引成本，不能把所有 first_pass 查询都称为冷索引请求。
